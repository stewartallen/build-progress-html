# CLAUDE.md — RV-10 Build Progress (static HTML dashboard)

## Overview

A single self-contained HTML file that renders the construction progress of an RV-10
aircraft kit: a GitHub-style contribution heatmap of daily build hours plus eight
statistics cards. Built for self-hosted deployment on a wall display, monitor, or phone.

**No build step, no runtime dependencies, no network calls except `progress.json`.**

## Files

| File               | Purpose                                                          |
| ------------------ | ---------------------------------------------------------------- |
| `index.html`       | The entire application — markup, CSS, and JS in one file         |
| `progress.json`    | Data, generated by [`build-progress-cli`](../build-progress-cli) |
| `eslint.config.js` | ESLint 9 flat config; lints the `<script>` block inside the HTML |
| `.prettierrc`      | 4-space indent, single quotes, 100-column width                  |
| `.editorconfig`    | UTF-8, LF, trim trailing whitespace                              |

## Data contract

`index.html` fetches `progress.json` and rejects anything that is not
`{ log: [...], statistics: {...} }`.

```json
{
    "log": [{ "date": "2022-02-02", "hours": 4.4 }],
    "statistics": {
        "total_hours": 1528.4,
        "days_worked": 473,
        "avg_hours_per_week": 7.9,
        "avg_hours_last_6_weeks": 3.4,
        "est_completion_date": "2028-02-25",
        "est_completion_date_6_weeks": "2031-04-09",
        "hours_current_week": 0.0,
        "hours_current_month": 7.0,
        "hours_last_30_days": 14.8,
        "current_streak": 0,
        "record_streak": { "days": 9, "start_date": "2023-06-30" }
    }
}
```

`log` entries are daily and may include zero-hour days; missing days render as level 0.
Dates are ISO `YYYY-MM-DD` and are **parsed and formatted as UTC everywhere** — see
"Dates" below.

## Architecture

The `<script type="module">` block has four parts, in order:

1. **Config and constants** — `CONFIG` (data URL, 2,500-hour goal, 15-minute refresh,
   15-second request timeout), heatmap geometry, colour cutoffs, `Intl` formatters.
2. **Statistics** — `STAT_CARDS` is a declarative array of `{ label, value, notes }`;
   `renderStatistics` clones the `#tpl-stat` template once per entry. Adding a metric
   means adding an array entry, not more markup.
3. **Heatmap** — `groupByYear` → `buildHeatmap` (plus `buildMonthLabels` /
   `buildWeekdayLabels`) produce one `<svg>` per year via `createElementNS`.
4. **Tooltip and data** — one delegated listener for every cell, then `fetchProgress`,
   `refresh`, and the visibility-aware refresh scheduler.

### Heatmap

Hand-drawn SVG — no charting library. One column per week, one row per weekday,
GitHub-style. Geometry is in SVG user units and scaled by the `viewBox`:

- 18×18 cells, 6px gutter, 2px corner radius
- 32px left gutter for the Mon/Wed/Fri labels, 20px top gutter for month labels
- Month labels anchor to the first _whole_ week of each month
- A full year is 1298×182 user units

The grid is generated from Jan 1 to Dec 31 directly, so cells from neighbouring years
are never created. Days in the future are not drawn.

### Colour scale

Five levels. `LEVEL_CUTOFFS = [0.1, 2, 4, 6]` — hours at or above each cutoff bump the
cell one step, so 6+ hours all render at the brightest step. Cells carry
`data-level="0..4"`; CSS maps that to the `--level-N` custom property, which is what
makes the scale theme-aware with no JavaScript.

| Level | Hours   | Dark      | Light     |
| ----- | ------- | --------- | --------- |
| 0     | 0       | `#30363d` | `#ebedf0` |
| 1     | 0.1 – 2 | `#0e4429` | `#9be9a8` |
| 2     | 2 – 4   | `#006d32` | `#40c463` |
| 3     | 4 – 6   | `#26a641` | `#30a14e` |
| 4     | 6+      | `#39d353` | `#216e39` |

### Responsive behaviour

There are **no layout breakpoints**. Instead:

- `clamp()` drives every font size and spacing value.
- The stats grid uses `repeat(auto-fit, minmax(min(100%, 15rem), 1fr))`. The `min(100%, …)`
  is what lets cards go full-width on a phone without a media query.
- Each chart SVG has `inline-size: 100%` between an explicit `min-inline-size`
  (62% of intrinsic, ≈11px cells) and `max-inline-size` (intrinsic, 18px cells). It
  scales down smoothly, then its container scrolls horizontally rather than shrinking
  cells into unreadable dots.

Media queries are reserved for `prefers-color-scheme`, `prefers-reduced-motion`, and
`print`.

### Theming

Every colour is a custom property on `:root`. Light is the base declaration; a single
`@media (prefers-color-scheme: dark)` block overrides the tokens. `color-scheme: light dark`
keeps scrollbars and form chrome in step, and paired `<meta name="theme-color">` tags
cover mobile browser chrome. Changing the palette means editing the token block — nothing
else.

### Dates

`new Date('2028-02-25')` parses as UTC midnight but formats in local time, which renders
the previous day for anyone west of Greenwich. Every date therefore goes through
`parseIsoDate()` and an `Intl.DateTimeFormat` pinned to `timeZone: 'UTC'`.

### Refresh

A self-rescheduling `setTimeout` (not `setInterval`) — a slow fetch can never overlap the
next one. The timer is cleared while the tab is hidden and fires an immediate refresh when
it becomes visible again. Fetches use `cache: 'no-store'` so a long-lived dashboard is
never served its own stale copy, and `AbortSignal.timeout()` so a hung request cannot
wedge the loop.

On failure the last good render stays on screen and only the status banner changes —
important for a wall display. Sections start `hidden` so a _first_-load failure shows the
banner alone instead of an empty legend over a blank grid.

### Accessibility

`<main>`, a real heading hierarchy, statistics as a `<dl>`, `role="status"` +
`aria-live="polite"` on the status line, `role="img"` with a per-year summary
`aria-label` on each SVG ("2024: 386.0 hours across 120 days"), a `<noscript>` fallback,
and `prefers-reduced-motion` honoured.

## Development

```bash
npm install       # dev tooling only; the page itself has no dependencies
npm run serve     # python3 -m http.server 8000
npm run check     # prettier --check && eslint
npm run fix       # prettier --write && eslint --fix
```

Run `npm run fix` before committing.

## Deployment

Copy `index.html` and `progress.json` to any static web server. To update the data,
replace `progress.json` — the page picks it up on the next refresh.

## History

Originally a hand-rolled vanilla-JS grid; migrated to Cal-Heatmap v4 (with D3, Popper,
and two plugins over CDN); then migrated back to hand-drawn SVG. The library was carrying
five CDN scripts, an undeclared `dayjs` global, a `setTimeout`-based hack to hide cells
that spilled across year boundaries, and leaked an instance per refresh cycle. Owning
~120 lines of grid math removed all four problems and made the page genuinely
self-contained.
